# 1.6.0 以图搜图

图库搜索框旁的「以图搜图」支持选图、拖入和 Ctrl/⌘+V；在图库空白处直接粘贴图片也会打开。用于从社交平台保存的旧图找回本机原图，搜索全部已启用图源，不继承当前文件夹、图版、日期、分类或颜色筛选。

结果区显示缩略图、文件名、完整路径及匹配分。点击缩略图查看详情；「复制完整路径」可在本机文件管理器中使用；「定位文件夹」跳回图库对应来源和目录，并按文件名定位。不会直接启动操作系统文件管理器。相同内容的不同文件分别显示，身份、笔记和图版不合并。

首次搜索会后台分批建立全库指纹，进度显示在搜索面板和既有状态中心。先显示已有索引的匹配，任务结束后自动重新搜索。关闭搜索面板会取消请求和轮询，后台共用的索引任务继续；再次打开可重用已完成的指纹。新增或修改图片需要正常图库刷新后加入检索。大图库首次索引需要读取原图，耗时取决于文件数量、分辨率和 SSD；搜索不会占用普通查询的两个线程。

参考图片只在内存中处理，不写入图库或磁盘，不发送外网。一次一张，最大 20 MiB；使用 Pillow 现有像素限额与解码保护。前端预览的对象 URL 在更换参考图或关闭面板后释放。

## 匹配范围

- 文件 SHA-256 一致显示「文件完全相同」。剪贴板和平台通常会移除元数据或重新编码，所以原图的粘贴副本可能显示为视觉匹配。
- 视觉匹配结合 EXIF 方向校正后的低频感知哈希、差异哈希、低分辨率颜色布局与宽高比，支持常见压缩和缩放。未引入模型、GPU、向量库或新 Python 依赖。
- 默认分数门槛 70；「扩大匹配范围」降至 55，最多返回 50 条候选。匹配分仅供排序，不是相同图片的概率。大幅裁剪、截图边框、拼图、遮挡、明显调色可能漏检；当前不提供语义或局部特征匹配。未命中不代表图库一定没有原图。
- 首轮匹配测试使用程序生成图像，覆盖 JPEG 压缩、缩放、小水印和 EXIF 方向。尚未用用户真实社交平台历史图片评估召回率。

## 后端契约

`POST /universal_gallery/api/images/search-by-image?minimum=70`：同源保护；multipart 仅一个名为 `image` 的文件；参数整数范围 55–95。最多两个同时接收/处理的搜索请求，饱和返回 503 与 Retry-After。参考图不会进入导入事务，不接受 URL 或任意路径。

返回 `matches`、`indexed`、`total`、`pending`、`failed`；有未处理资源时返回 `job`。每条匹配包括 `image`（兼容 ImageRecord 和 asset_id）、`score`、`match_type`（exact/similar）、`full_path`。候选路径再次经过图源安全解析，物理大小和纳秒修改时间不匹配的候选不会返回。已损坏的库图片仍可浏览；如果文件哈希可读，可参与完全相同文件匹配。

全库任务是既有公开 `fingerprint_assets`，payload 仅 `{ "whole_library": true }`，不允许与范围参数混用。任务使用 keyset 分批遍历全部图片，支持去重、重启、检查点取消及既有重试；普通范围预热保持原有上限。指纹版本升至 3，SQLite 派生 schema 升至 10，用户 JSON 与权威目录库格式不变。重建指纹不改变资源 ID。

验证：`python -m pytest tests/test_image_search.py -q`、前端 `ImageSearchModal.test.tsx`，以及对隔离示例运行 `python scripts/browser_image_search.py http://127.0.0.1:8196`。浏览器用例覆盖真实剪贴板、压缩图、路径复制、目录定位、移动视口、零导入请求与零 JS 错误。
