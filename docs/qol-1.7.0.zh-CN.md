# 1.7.0 本地候选版：使用与验证说明

本版保留 React/Vite、aiohttp、SQLite、JSON 用户状态、资源身份和文件事务。没有引入搜索模型、媒体类型或数据库。候选版在本地验证；没有自动推送、创建 Release 或发布 Registry，`v1.6.0` 标签不变。

## 使用变化

- **自动同步**：ComfyUI 工作流成功、失败或中断后，完成事件在一秒内合并，再提交持久刷新任务。可见图库每 15 秒检查 freshness；后台暂停。关闭设置中的自动同步会同时关闭事件和轮询。加载先读已提交快照，再异步校准首次基线。
- **保留位置**：最新排序第一页、靠近顶部且没有选择、拖动或详情编辑时可以直接显示新图。其他情况下更新目录统计，保留当前图片并显示“有新图片，点击查看”。非图库工作区不获取图片分页。
- **更新说明**：右上角查看本机版本和历史说明，断网仍可读；检查失败、缓存、示例和已核验最新分开展示。升级提示每版本一次，首次安装只记基线；红点只表示远端新版。GitHub 发布不代表 Registry 已审核。
- **任务中心**：右下角最多三条浮动提示，展开查看进行中、失败和最近完成。关闭提示不取消任务；只有可取消后台任务提供取消入口。完成历史最多保留 50 条会话记录，持久任务继续由后端保存。
- **信息密度**：设置中选择标准或紧凑；网格列数独立保存。两种密度共用虚拟布局和框选估算，元信息不低于 12px。现有偏好不被重置。
- **以图搜图**：参考图、结果与滚动位置在详情和定位过程中保留；定位打开真实父目录和目标分页，支持返回原浏览位置。明确关闭后释放参考图。修复再次点击被同一次窗口外点击事件关闭、以及定位后仍处于隐藏状态的问题。
- **垃圾箱批量操作**：整批只使用一条操作记录；逐项保留已有文件事务，遇到首个失败停止，不宣称整批原子提交。只清除成功选择，未完成项保留并可重新确认后重试。整批结束只读取一次已提交列表和目录，不再为每项创建整库扫描。
- **刷新可靠性**：同范围扫描不因每次目录库 generation 改变而创建新任务；取得扫描锁后才记录 generation，提交前继续拒收过期扫描。可重试错误仍限同一任务最多三次（间隔 2 秒、10 秒）。终止失败后暂停该范围、该脏版本的自动重试；手动重试或新工作流输出可再次尝试。定时检查和聚焦不会无限创建失败任务。重启时旧版积压的同范围重复刷新只重放最新一项，其余保留任务记录及 `superseded_by`，不删除历史。

## 本地示例

```powershell
python scripts/preview.py --port 8196
# 另一实例，仅用于批量操作验收；所有内容均为独立临时样例
python scripts/preview.py --port 8198 --trash-items 385
```

打开 `http://127.0.0.1:8196/gallery/`。示例不加载真实图源、不运行 GPU 推理；退出进程后临时状态不作为用户数据保留。`--trash-items` 上限 500；示例中的“移至系统回收站”仍走正常文件操作，因此生成的样例可出现在系统回收站。

## 接口与偏好

接口细节见 [架构说明](architecture.md#17-qol-contracts)。新增只读 `/release-notes` 和 `/images/locate`，原有图片路径字段和 API 保留。`UiPreferences.interfaceDensity` 为可选的 `standard|compact`；旧偏好正常读取。用户 JSON 不迁库，目录库不重建，普通消息不新增数据库。

结构化版本说明维护于 `docs/releases/<version>.json`，必须同时提供中文和英文。运行 `python scripts/release_notes.py` 生成 CHANGELOG，`--check` 检查一致性，`--body en` 或 `--body zh-CN` 输出发布正文。构建产物包含 `release-version.json`；发布检查校验源码版本、锁文件、说明和 dist 版本。

## 安装与恢复

1. 停止 ComfyUI，备份用户状态、图源、词库、目录库和未解决事务日志。
2. 完整替换代码与整个 `gallery_ui/dist`，不可只覆盖部分同名资源。
3. 重启 ComfyUI，并刷新其页面和图库，加载新的完成事件桥接。后端修改无法只靠刷新网页生效。
4. 如有恢复日志，按 [基础架构恢复说明](foundation-1.6.0.zh-CN.md) 处理；不要删除日志或自动重建目录库。

回退前确认没有未解决事务，恢复旧代码与完整旧 dist，继续保留兼容 JSON 和目录库历史。不要用旧备份直接覆盖新版使用期间的用户编辑。
